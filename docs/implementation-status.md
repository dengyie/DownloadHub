## 最终实现选择

- 继续采用 Go + SQLite + OpenList，没有引入新的服务、前端框架或通用数据访问抽象。
- 资源列表使用 JSON；grant 和扣次审计独立持久化。固定 schema 版本，迁移失败整体回滚，未知未来版本拒绝打开。
- 外部请求共享 8 秒预算，总请求 10 秒，HTTP 写超时 15 秒。数据库事务不包围外部网络请求。
- 上游有效期采用经运维验证的 `openlist_min_url_ttl_seconds` 下界，默认 0 阻止启动；不从未经证实的签名格式猜测期限。绝对下载 URL 必须匹配 `download_hosts`。
- 新卡必须显式指定 `--resource` 或 `--prefix`。默认公开目录 `pub/` 拒绝付费签发，实际值必须与 nginx alias 保持一致。
- `/ready` 验证数据库并提供基础计数，不代表 OpenList 可用；未实现独立的后端探测器、延迟分位数指标或容量基准。容量目标需按实际业务建立。

## 验证证据

- `make check`：Go vet、完整 race 测试、14 个 Node 前端测试、gofmt 和 diff 检查。
- Go 62 个顶层测试；专项涵盖迁移回滚/重启、数据库等待后到期、审计写入失败回滚、跨连接扣次唯一性、租约接管、取消、路径往返和代理信任。此前覆盖率测量为 70.1%，最终以当前测试输出为准。
- `make build-linux`：Linux amd64 静态二进制。
- 本地真实浏览器与模拟 OpenList：错误后重新兑换、首次扣次、同凭证重试不再扣次、零余额恢复、完整 URL 复制通过。390×844 视口无横向溢出，亮色提示对比已修正。
- 额外 CLI 回归曾复现不传授权路径也创建卡并写库；移除默认目录授权后，拒绝输入且不触碰数据库。
- 上述不等同于真实 OpenList 传输、线上 nginx 或生产恢复验收。未消费正式卡，未修改生产配置或文件。

## 原发布门槛（2026-10-01 结果见发布记录）

详见 [生产核验与发布步骤](production-readiness.md)。最重要的未决项是：

1. 唯一卡绑定 `pub/manual.txt`，且该路径确实匿名可读。确认它是公开样例还是需保护的资源；受保护资源必须离开公开 alias 和缓存。
2. 验证 OpenList 返回 URL 的公网路径、host、最短剩余签名寿命以及重启/凭据轮换行为。
3. 查明 MySQL 拒绝连接及短 uptime 的原因，完成 acg-faka 订单/支付依赖盘点；查证备份来源并做隔离恢复。
4. 按维护窗口停止所有旧写入者，在生产一致性副本上演练新 schema，验证配置与真实 nginx，再切换单一写入服务。

本分支是包含 schema 和协议变化的整体候选版本。**不能只回退二进制并继续使用迁移后的数据库**。上线产生新扣次后，数据库回退必须停写、保全两边快照并对账，优先前向修复。
